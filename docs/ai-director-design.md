# Aloria Director — ИИ-режиссёр экономического мира

> Технический дизайн сервиса, который делает рынок Алории живым: макроциклы,
> события, новости и целевые цены, к которым маркетмейкер тянет стакан.
> Концепция и философия — в `docs/macro-economy-concept.md`. Здесь — как это
> устроено внутри и как встроено в контур terex.

---

## 1. Как устроен terex на самом деле (результаты разведки)

Поток команды: `connectorCommands` (RabbitMQ topic, ключ `TEREX.{Board}.False`,
protobuf-net) → **terex.router** (единственный gRPC-клиент; sequential,
replica=1) → **terex.orderprocessor** (in-memory FIFO matching, стакан в RAM,
бэкап в Postgres) → BrokerOrders/BrokerTrades/AnonymousTradesV2 →
**terex.marketdata** (стакан/котировки → Redis + RabbitMQ Streams; свечи строит
внешний warp-контур из стрима).

Факты, определившие дизайн:

| Факт | Следствие для режиссёра |
|---|---|
| «Целевой цены» в terex нет: генератор котирует вокруг `(HighLimitPrice+LowLimitPrice)/2` из `instruments` | Целевые цены живут в **таблице режиссёра**, а не в лимитах |
| Коридор `[Low,High]` кэшируется orderprocessor'ом **на старте**, дельты несут только TradingStatus | Лимиты на лету не двигаем; при сиде ставим коридор **широким** (×0.25…×4 от стартовой цены), чтобы он не мешал |
| Существующие генераторы читают инструменты **один раз** | Новый генератор **периодически перечитывает** цели из БД |
| Клиент `GEN` захардкожен в router (без ответов/логов) | Новый генератор тоже ходит от `GEN` |
| Валидация: `Price % MinPriceIncrement == 0`, целые количества, статус Trading | Квантование цен decimal (без int-каста — баг H-5), целые объёмы, фильтр по статусу |
| MassCancel кладёт аудит роутера (F-4), router однопоточный | Не используем MassCancel; поток заявок умеренный |
| `instruments` никто не пишет из кода (руками) | Режиссёр **сидит вселенную сам** (idempotent SQL) |
| В `instruments` уже есть Volatility, TheorPrice, MaturityDate, FaceValue, InitialMargin*, CFICode | Готовые поля под облигации и будущие деривативы |

```
                                                     TargetPriceCommandsGenerator
                                                     (НОВЫЙ класс: лестница котировок
                                                      вокруг цели, GEN, шум, тейкеры)
                                                              │ connectorCommands
                                                              ▼
                                              router → orderprocessor → marketdata
```

Три исполняемых режима `Aloria.Director`:
- `run` — боевой tick-loop (реальное время, пишет в Postgres + aloria-api);
- `simulate --days N` — быстрый прогон N дней мира без внешних систем
  (LLM-шаблоны, trace в JSONL) — для тестов, баланса и презентаций;
- `seed` — идемпотентный засев вселенной в `instruments` + `director.*`.

Ядро (`Aloria.Director.Core`) — чистая библиотека без I/O: весь мир, вся
математика, генераторы под seed'ом. Адаптеры (Postgres, OpenRouter, aloria-api)
живут в хосте. Это делает мир тестируемым и воспроизводимым.

## 3. Модель времени

- 1 мировой день = 1 реальный день; **цикл = 10 дней ≈ «год»**.
- Тик режиссёра — раз в `TickMinutes` (по умолчанию 15 мин → 96 тиков/день).
- Календарь генерируется на цикл вперёд: отчётности (каждой компании — 1 раз
  за цикл), отсечки и выплаты дивидендов, купоны (каждые 1–2 дня), погашения,
  заседание ЦБ (1 раз за цикл), экспирации (задел под деривативы).
- Времена суток событиям раздаёт сэмплер; плановые события исполняются в свой тик.

## 4. Макро-слой

Состояние: ключевая ставка `r`, инфляция `π`, рост `g`, аппетит к риску `ρ`,
режим `R ∈ {expansion, peak, recession, recovery}` + флаг кризиса.

- **RegimeMachine** — полумарковская петля: длительность режима ~ Gamma,
  переходы по кругу с малой вероятностью «срезки» (перегрев → сразу рецессия).
  Кризис — оверлей: макрошок с severity>0.9 форсирует рецессию, волатильность ×3,
  корреляции секторов → 1.
- `π`, `g` — Орнштейн–Уленбек к режимным средним; `r` меняется только на
  заседании ЦБ: `Δr = clamp(a·(π−π*) − b·(g−g*) + шум)` — политика по Тейлору,
  с сюрпризом против консенсуса.

## 5. Секторы и эмитенты

У сектора: беты `β_g, β_r, β_π`, собственная волатильность, класс цикличности.
Дневной лог-дрейф сектора: `μ_s = β_g·(g−ḡ) − β_r·(r−r̄) − β_π·(π−π̄) + shock_s`.

У компании: скрытая **справедливая стоимость** `F_i` (лог-блуждание с дрейфом
сектора + идиосинкразический шум + скачки событий), EPS-трек, дивидендная
политика, долговая нагрузка (кредитное качество для облигаций).

## 6. Ожидания и сюрприз — сердце реализма

Для каждого планового события живёт **консенсус** `E[x]`:
- за 1 день до события публикуется новость-ожидание («аналитики ждут…») и
  цена частично закладывает ожидание (pre-move);
- в момент события реализуется факт `x` (стохастически вокруг тренда);
- **сюрприз** `z = (x − E[x]) / σ_E`; движение цены: `Δlog F = k · tanh(z/2) · scale`.

Так возникают «продай на факте», рост на плохой-но-лучше-ожиданий отчётности и
падение на хорошей-но-уже-в-цене — честно, без ручной подкрутки.

## 7. Ценообразование

- **Акции**: целевая цена `T_i` тянется к `F_i` с гравитацией
  `dT = λ(F−T)dt + σ_i dW` — рынок «узнаёт» справедливую цену постепенно.
- **Облигации** (цена в % номинала): `P = Σ CF_t · e^{−(r+s_i)·τ_t}`,
  где спред `s_i` = кредитное качество + режимная премия + дистресс.
  Купон из календаря; **дефолт** — хвостовое событие: купон пропущен,
  цена → recovery (30–50%), новость и статус эмитента «distressed».
  НКД начисляется непрерывно (в terex НКД идёт от фида — задел).
- **Фонды**: NAV-трекинг корзины (индексный ALIN — всё по капитализации;
  облигационный ALBF — корзина бондов), цель = NAV + шум трекинга.
- **Деривативы (задел, класс `DerivativesMath`)**:
  форвард `F = S·e^{(r−q)τ}`; опционы Black–Scholes–Merton (+ греки, паритет);
  фьючерсная целевая цена = форвард от целевой цены базового актива;
  запись в `instruments.TheorPrice/Volatility` — поля уже существуют.
  Юнит-тесты: пут-колл паритет, монотонность, сходимость к внутренней стоимости.

## 8. Событийный слой (RNG-сэмплер, без LLM)

- Приходы — Пуассон на тик, интенсивность зависит от режима.
- Охват: company / sector / macro (веса), кандидаты — по экспозиции секторов.
- **Серьёзность** — смесь: тело Beta(2,5) + хвост Парето(α≈1.5) с шансом ~7%;
  масштаб импакта: company ≤ ±12%, sector ≤ ±6%, macro ≤ ±4% (широким фронтом).
- Знак — с режимным перекосом (в рецессию хуже). Длительность: скачок /
  «тление» N тиков / временный (mean-reverting) шок.
- Сэмплер сидируется (`Seed` в конфиге) — мир воспроизводим.

## 9. LLM-режиссёр (OpenRouter)

- Вход: снапшот мира + спек события (охват/знак/серьёзность/длительность/пул
  кандидатов) + последние заголовки (антидубль) + лор вселенной.
- Выход — строгий JSON: `{symbol?, channel, headline, body, sentiment}`.
  Валидация схемы, 1 retry, при недоступности/ошибке — **шаблонный fallback**
  (мир никогда не останавливается из-за LLM).
- LLM выбирает *историю* и жертву из пула; **числа решают RNG и формулы**.
- Конфиг: `OPENROUTER_API_KEY`, модель (`Director:Llm:Model`), температура.

## 10. Схема данных режиссёра (Postgres terex, схема `director`)

```
director.world_state      (singleton: день, тик, режим, r, π, g, ρ, кризис, seed)
director.issuers          (эмитент: сектор, качество, EPS, политика дивидендов, distressed)
director.price_targets    (symbol → target_price, sigma_daily, drift, updated_at)  ← читает генератор
director.calendar_events  (day, tick, type, symbol?, payload, status)
director.events_log       (журнал случившегося: спек + сюрприз + примененный импакт)
director.news_outbox      (новости на отправку в aloria-api, с retry)
```

`instruments` сидится идемпотентно (по образцу `terex_instruments_seed.sql`):
широкие коридоры, шаг цены, лоты, FaceValue для облигаций, CFICode.

## 11. Новый генератор в terex.ordergenerator

`TargetPriceCommandsGenerator` (новый класс, старые не тронуты; регистрация —
добавленная строка в Program.cs, опции `Terex::TargetGenerator` с severity
Warn — без конфига генератор просто выключен):

- раз в `TargetsRefreshSeconds` перечитывает `director.price_targets` +
  `instruments` (лимиты/шаг/статус);
- держит локальный `lastMid` по инструменту; каждый тик двигает его к цели:
  `mid += clamp(gap·Pull, ±MaxStepTicks·step) + шум(σ)`;
- котирует **лестницу** лимиток вокруг mid: спред = max(2 шага, k·σ·mid),
  2–4 уровня на сторону, объёмы ~ логнормальные, редкие рыночные заявки-тейкеры
  в сторону цели (вероятность ∝ |gap|) — «съедают» устаревшие уровни;
- цены квантуются к `MinPriceIncrement` (decimal!), клампятся в коридор,
  объёмы целые, статус != Trading → пропуск тика;
- клиент `GEN`, TIF: лимитки OneDay, рыночные FoK.

## 12. Интеграция с aloria-api

Режиссёр — писатель контента через HTTP (админ-роуты):
- `POST /api/admin/market/news` — новость (headline/body/sentiment/type/scope/symbols/sector);
- `PUT  /api/admin/macro/state` — режим/ставка/инфляция/день цикла (уже было);
- `POST /api/admin/market/calendar` + `GET /api/v1/macro/calendar` — календарь
  цикла (приложение перестанет мокать его на клиенте).

## 13. Наблюдаемость и управление

- `GET /director/state` — мир целиком (режим, ставка, эмитенты, цели);
- `POST /director/regime` — ручной рычаг макроцикла (единственный ручной);
- `simulate` пишет JSONL-трейс: по тику — цены/факторы/события → графики.

## 14. Риски и что учтено

- Правка `instruments` на лету не видна сервисам → не полагаемся на неё вовсе.
- Роутер однопоточный → интенсивность потока заявок конфигурируема и скромна.
- LLM недоступен → шаблонный fallback, мир не останавливается.
- Пустой снапшот WS в приложении при нулевой активности → генератор котирует
  с первого тика после сид-старта.
- Все случайности — от одного seed: прогон воспроизводим.
