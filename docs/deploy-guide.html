Aloria: деплой ИИ-режиссёра и вся связка

Что где живёт, какие правки внесены в terex, в каком порядке разворачивать и как проверить, что мир ожил. Состояние на июль 2026, ветка prototype/macro-world-extras.

1. Карта системы

Приложение Aloria (Flutter)iOS / Android / Web. Торгует через торговый API Алора; новости, макро, календарь и справочник берёт из aloria-api.
aloria-admin (React + Vite)Админка: контент + «Мир» (управление режиссёром). Проксирует /api → aloria-api, /director → режиссёр.
▲ читают контент ▲    ▼ админ-ручки ▼
aloria-api (ASP.NET + SQLite) :5050Клиентский бэк контента: новости, макро-состояние, календарь цикла, справочник мира. Хранит то, что напушил режиссёр.
Aloria.Director (ASP.NET) :5077ИИ-режиссёр: экономика мира (RNG + формулы), новости (LLM/шаблоны), целевые цены. Admin-API для «Мира» в админке.
▼ director пишет целевые цены в схему director той же Postgres ▼
Postgres terexinstruments (справочник движка, сидится режиссёром) + схема director: price_targets, world_state, events_log.
terex.ordergenerator+ новый генератор TargetPriceCommandsGenerator: читает price_targets, котирует лестницу лимиток и тейкеров клиентом GEN.
Terex.Router → OrderProcessor → MarketDataРеальный мэтчинг: заявки идут через RabbitMQ (connectorCommands), стакан и сделки — в торговый API.

Два контура:

  • Контур цены (реальный рынок): режиссёр считает целевые цены → пишет в director.price_targets → ordergenerator тянет середину стакана к цели настоящими заявками → мэтчинг в OrderProcessor → котировки/стакан/свечи в приложении. Ученики торгуют в том же стакане и тоже двигают цену.
  • Контур истории (контент): режиссёр пушит в aloria-api макро-состояние, новости, календарь цикла и справочник мира → приложение и админка читают их по HTTP.

3. Правки в terex — что именно сделано

Патч лежит в двух местах: применён в ~/Documents/warp/Downloads/terex.ordergenerator-master/ и продублирован в репо aloria-director/terex-patch/ (источник правды для переноса).

Новые файлы (старые генераторы не тронуты)

ФайлРоль
Services/TargetPriceCommandsGenerator.csСам маркетмейкер: тянет mid к целевой цене, котирует лестницу, шлёт тейкеров.
Data/ITargetsDataProvider.cs + TargetsDataProvider.csЧтение director.price_targets и инструментов из Postgres (Npgsql, raw SQL). Если схемы нет — пустой список, не падает.
Models/TargetInfo.csDTO целевой цены.
Configuration/TargetGeneratorOptions.csОпции генератора (см. конфиг ниже).

Правки существующих файлов — всего 2×2 строки (описаны в terex-patch/PATCHES.md)

  • Configuration/GeneratorOptions.cs — свойство TargetGeneratorOptions с [AlorSettings(..., SourceName = "Terex::TargetGenerator")], severity Warn: нет секции в Identity — генератор просто выключен, сервис ведёт себя как раньше.
  • Configuration/ServiceCollectionExtensions.cs — регистрация TargetPriceCommandsGenerator и TargetsDataProvider в DI.

Как работает генератор

  • Раз в TargetsRefreshSeconds (10 с) перечитывает целевые цены и инструменты.
  • Держит локальную середину; за одно котирование подтягивает её на PullFactorPct (25 %) разрыва к цели, но не больше MaxStepTicks (40) шагов цены + шум NoiseSteps (±3 шага).
  • Спред = max(2 шага, 0.8 × дневная σ × цена); лестница DepthLevels (3) уровней в обе стороны, лимитки клиентом GEN, TIF OneDay.
  • С вероятностью TakerProbPct (8 % + больше при большом разрыве) шлёт рыночную заявку в сторону цели — лента сделок живёт.
  • Цены квантуются к MinPriceIncrement через decimal (без int-каста — та самая грабля H-5 из старых генераторов обойдена), объёмы целые.

4. Деплой по шагам

  1. Прероквизиты. .NET 10 runtime на хосте режиссёра и aloria-api; доступ к Postgres terex с правом создавать схему; сетевой доступ режиссёра к aloria-api; ключ OpenRouter (не обязателен — без него новости пишет шаблонный нарратор).
  2. aloria-api. dotnet publish aloria-api/src/Aloria.Api -c Release, запуск бинаря. Порт из appsettings.json ("Port": "5050"). SQLite-файл создаётся сам, все таблицы — bootstrap при старте. Ничего сидить не нужно: контент напушит режиссёр.
  3. Сид инструментов terex. Один раз: 
    cd aloria-director/src/Aloria.Director
DIRECTOR_TEREX_DB="Host=…;Database=terex;Username=…;Password=…" \
  dotnet run -- seed
    Идемпотентно: создаёт схему director (price_targets / world_state / events_log) и вставляет 24 инструмента вселенной в instruments (raw SQL — у таблицы surrogate PK GENERATED ALWAYS, EF туда писать нельзя). Ценовые коридоры широкие (×0.25…×4 от старта), чтобы лимиты движка не мешали жизни цены.
  4. Режиссёр. dotnet publish -c Release и запуск с конфигом (env-переменные перекрывают appsettings.json): 
    # мир
Director__Seed=20260701          # зерно мира (видно и меняется в админке)
Director__TicksPerDay=96
Director__TickSeconds=900        # 900 = мировой день за сутки; в dev ставим 15
Director__Port=5077
# интеграции
Director__AloriaApi__Enabled=true
Director__AloriaApi__BaseUrl=http://<aloria-api>:5050
Director__TerexDb__Enabled=true
DIRECTOR_TEREX_DB="Host=…;Database=terex;…"
# новости через LLM (опционально)
Director__Llm__Enabled=true
Director__Llm__Model=openai/gpt-4.1-mini
OPENROUTER_API_KEY=sk-or-…       # только env, в конфиги/git не класть
    При старте режиссёр сам: восстановит/создаст мир, запушит справочник и макро в aloria-api, начнёт тикать и писать целевые цены.
  5. Патч ordergenerator. Разложить файлы из aloria-director/terex-patch/ по Terex.OrderGenerator/ (таблица соответствия в README патча), внести 2×2 строки из PATCHES.md, собрать (нужен корпоративный NuGet/VPN). В Identity добавить секцию Terex::TargetGenerator: 
    {
  "MinIntervalMs": 800,  "MaxIntervalMs": 2500,
  "TargetsRefreshSeconds": 10,
  "PullFactorPct": 25,   "MaxStepTicks": 40,  "NoiseSteps": 3,
  "SpreadSigmaFactorPct": 80,
  "DepthLevels": 3,      "LevelStepTicks": 2,
  "MaxLimitQuantity": 40,
  "TakerProbPct": 8,     "MaxMarketQuantity": 10
}
    Выкатить ordergenerator. Откат простой: убрать секцию из Identity — генератор выключен.
  6. Админка. npm run build в aloria-admin; в прод-раздаче нужен реверс-прокси: /api → aloria-api:5050, /director → режиссёр:5077 (в dev это делает vite). Вкладка «Мир» — рычаги, ансамбль-симуляции, просчёт будущего, зерно.

5. LLM-новости: модель и стоимость

Дефолт — openai/gpt-4.1-mini (выбрана тестом на боевом промпте: держит знак события, придумывает конкретные продукты, чистый русский, ~2.4 с на новость). Стоимость ≈ $0.0005 за новость — при 10–20 LLM-новостях в день это меньше $0.3 в месяц. Хочется красивее — anthropic/claude-haiku-4.5 (~$0.002/новость, всё равно копейки). Механические новости (купоны, отсечки, выплаты) LLM не трогают — токены не жгутся. При ошибках LLM: 1 ретрай → шаблонный фолбэк → после 3 подряд провалов пауза 5 минут (circuit breaker). Мир без сети не останавливается.

6. Грабли и нюансы

  • Порядок запуска: aloria-api → режиссёр (иначе первый пуш справочника уйдёт в warning; следующие макро-пуши всё равно догонят, а справочник — при рестарте).
  • Детерминизм: мир полностью определяется зерном; состояние RNG сохраняется в снапшоте, поэтому «Просчёт» в админке показывает точное будущее. Кнопки «кризис»/«режим» и смена зерна — это осознанное вмешательство, после них будущее другое.
  • Рестарт режиссёра: с включённой TerexDb состояние мира персистится в director.world_state и мир продолжается; в dev без Postgres рестарт = новый мир с day 1.
  • Ключ OpenRouter — только через env (OPENROUTER_API_KEY). Не в appsettings, не в git, не в логи.
  • Часовые пояса: всё в UTC; SQLite теряет DateTimeKind — в DTO aloria-api уже стоит SpecifyKind(Utc), не убирать.
  • instruments в terex — рукописная таблица с DDL, отличающимся от EF-модели: только raw SQL (сид так и сделан).
  • MassCancel в terex ломает аудит роутера (известная проблема F-4) — генератор его не использует.
  • Просчёт (foresight) — по умолчанию 30 дней, потолок 120 (Director__Foresight__*): спойлер-гигиена для админа.
  • Ученики двигают цену в том же стакане. Пока обратной связи «активность учеников → мир» нет; когда появится — точный просчёт будущего перестанет быть точным (осознанный размен).
Короткая версия: поднять aloria-api → прогнать seed → запустить режиссёра с env-конфигом → разложить патч ordergenerator + секция Identity → собрать админку за прокси → пройтись по чек-листу. Всё остальное система делает сама.
