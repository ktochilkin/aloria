# Экономический мир Aloria — концепция

> Источник правды по «живой экономике» Aloria: экономические циклы, события, новости,
> как всё это двигает цену в торговом движке, и какая роль у ИИ. Этот файл — про **что и почему**.
> Техническая реализация бэков — в конце, раздел «Архитектура».

## 1. Зачем

Сейчас рынок в Aloria живёт за счёт бот-генератора (`terex.ordergenerator`, портфель `GEN`),
который тянет цену к **целевой цене** инструмента в БД. Целевую цену пока почти ничто
осмысленно не двигает: новости генерятся отдельным n8n-пайплайном со **случайным**
`impact_score`, пишутся в таблицу новостей торговой системы и **на цену не влияют** — причинность
оборвана.

Цель — построить **живой экономический мир**: единый для всех учеников, автономный, со
случайными событиями (вплоть до кризисов), где новость и движение цены связаны честно и
поучительно, а не декоративно.

## 2. Философия

- **Один общий живой мир.** Не персональные сценарии. Ученик подключается в любой момент и
  просто наблюдает, что происходит на рынке сейчас. Мир один для всех.
- **Автономно и на рандоме.** Единственный опциональный ручной рычаг — **макроцикл**
  (можно задать вручную). Всё остальное — события, их сила, знак, тайминг — генерится само.
- **Не приучать к наивным корреляциям.** Рынок должен ломать заученные рефлексы, а не закреплять
  их. Хорошая новость ≠ цена вверх. Высокая ставка ≠ всё падает. (Как именно — раздел 6.)
- **Реальные участники тоже двигают цену.** Движок настоящий (FIFO-матчинг), заявки учеников в
  том же стакане — это дополнительный, неустранимый источник непредсказуемости.
- **Сценарный режим под уроки — отклонён.** Мир не подгоняется под конкретный урок; урок
  опирается на то, что в живом мире и так регулярно случается.

## 3. Модель времени

- **Экономический цикл ≈ 10 дней = «год».** На время цикла задаётся макрорежим.
- Внутри цикла — **детерминированный календарь**: отчётности компаний, отсечки под дивиденды,
  купонные даты, погашения облигаций, решение «ЦБ» по ставке, экспирации (деривативы — потом).
- **Выплаты дивидендов/купонов — короткий цикл ≈ 1 день**, чтобы ученик быстро «пощупал» то,
  что в реальности ждут кварталами. Время сжато — это честно проговаривается в уроках.

Ритм календаря важен педагогически: ученик может **предвосхищать** события, а предвосхищение —
это уже навык.

## 4. Слоистая модель мира

Снизу вверх, каждый слой питает следующий:

0. **Часы и календарь** — симуляционный clock; плановые события дня.
1. **Макрорежим (погода цикла)** — расширение → перегрев → кризис/рецессия → восстановление.
   Задаёт ключевую ставку, инфляцию, аппетит к риску, базовую волатильность. Переходы идут по
   правдоподобной петле, не чистый рандом.
2. **Секторы** — у каждого своя чувствительность (беты) к макрофакторам.
3. **Компании** — фундаментал (выручка, маржа, долг, справедливая стоимость), сектор + свои
   идиосинкразические события. Раз в цикл — отчётность.
4. **События** — плановые (из календаря) и стохастические шоки (см. раздел 6).
5. **Цена → движок** — фундаментал + события → **траектория целевой цены** + волатильность.
   Целевая цена отдаётся движку как **гравитация**, не телепорт: бот-маркетмейкер тянет к ней,
   реальный ордерфлоу может временно увести.

## 5. Перевёрнутая причинность

Было: `random → новость → (ничего)`.
Стало: **`состояние мира → цена → новость как объяснение`**.

Существует числовая «правда мира», которая меняется по понятным законам. Цены выводятся из неё.
Новость — это **поверхностный сигнал** изменения состояния, а не его причина. Ученик видит
новость → видит, как поехала цена → улавливает связь причина-следствие. Это сильнейший учебный
крючок, и сейчас он не работает, потому что связи нет.

## 6. Разделение ответственности: RNG / LLM / формулы

Три владельца на каждый тик, не пересекаются. Это и есть ответ на вопрос «как грамотно встроить ИИ».

```
ТИК
 1. ЧАСЫ/КАЛЕНДАРЬ (детерминир.) — плановые события дня
 2. RNG-СЭМПЛЕР СОБЫТИЙ (БЕЗ LLM) ← здесь «характер рынка» и кризисы
      • случился ли шок?                         (частота прихода)
      • охват: макро / сектор / компания          (веса)
      • СЕРЬЁЗНОСТЬ из тяжёлохвостого распределения (кризис редко; хвост толще в «перегреве»)
      • длительность: мгновенный / тление
      • пул кандидатов (кого задевает)            (по экспозиции секторов)
      → АБСТРАКТНЫЙ спек события, без текста и без чисел цены
 3. LLM-РЕЖИССЁР (в рамке из п.2, на основе данных)
      вход: состояние мира (режим, ставка, фундаментал и ОЖИДАНИЯ) + спек + недавние новости
      решает: ЧТО конкретно произошло (живая история), какую компанию из пула,
              канал (издержки/спрос/логистика), заголовок + текст + sentiment + symbols
      НЕ решает: силу движения цены — она задана серьёзностью из п.2
 4. ЯДРО ЦЕН (формулы, БЕЗ LLM)
      серьёзность + состояние → сдвиг фундаментала (беты секторов)
      → СЮРПРИЗ = факт − ожидание   (именно это двигает цену)
      → траектория целевой цены + волатильность
      → облигации: механически из ставки/спреда; дефолт → купон мимо + обвал
      → пишет целевые цены движку (гравитация); обновляет ОЖИДАНИЯ
 5. ПУБЛИКАЦИЯ: новость (из п.3) в стор; цена уже едет
```

**Почему рандом, а не «попросить LLM придумать событие».** LLM сама никогда не сгенерит кризис
или хвостовой сценарий — у неё нет чувства частоты («раз в N тиков — обвал») и тяги к крайностям,
она тяготеет к умеренному и безопасному. Поэтому **опасные числовые решения — наступил ли шок,
насколько сильный, кого по охвату, включая редкие кризисы — рождаются из распределений в коде,
до того как LLM вступает.** LLM работает уже внутри заданной рамки.

Разграничение:
- **RNG владеет** статистикой мира: быть ли беде, насколько сильной, кого, длительность, кризисы.
- **LLM владеет** человеческим слоем: какая история, какая компания из пула, как написать текст.
  Решения качественные и выборочные, не числовые; на основе реальных данных состояния.
- **Формулы владеют** всей математикой: фундаментал, сюрприз vs ожидания, траектория цены,
  облигации, волатильность, обновление ожиданий.

Тюнинг-параметр: ширина пула кандидатов, который RNG отдаёт LLM. Узкий = контроль и баланс,
широкий = разнообразие. По умолчанию RNG фиксирует охват+серьёзность+длительность, выбор
конкретной компании из пула — за LLM.

## 7. Принципы реализма (как ломается наивность)

- **«Уже в цене» / sell-the-news.** Между новостью и движением стоит слой **ожиданий**: цена
  реагирует на `сюрприз = факт − ожидание`, а не на уровень новости. Ждали отличный отчёт и он
  вышел отличным → движения нет или даже распродажа. Ждали провал, вышло «просто плохо» → рост на
  плохой новости. У каждой компании/сектора живёт «ожидаемая» величина, событие несёт сюрприз.
- **Разные беты секторов.** Один макросдвиг даёт разнонаправленную реакцию: ставка вверх — банки
  скорее плюс, закредитованный туризм/ритейл минус, защитная еда/вода ≈ нейтрально. Правило
  «ставка ↑ → продаю всё» вывести нельзя — и это правильно.
- **Поток и шум.** Случайный блуждающий компонент + реальные заявки участников. «Хорошая новость
  → цена вниз» может возникнуть даже без сюрприза — просто потому что кто-то крупно продал.

Каждое контринтуитивное движение при этом **объяснимо постфактум** — материал для уроков про
риск, волатильность и ожидания.

## 9. Архитектура

### Топология сейчас (на что ходит Flutter)

- **TEREX (торговая система), `api.alor.dev`** — C#/.NET. WS маркет-дата, REST-торговля,
  `/news/graphql` (фильтр только по `symbols`). Новости сегодня — отсюда; это та же MSSQL-таблица,
  в которую пишет n8n. Не расширяемо (нет секторов/типов событий).
- **aloria-api, `:5050`** (`ALORIA_API_URL`) — C#/.NET, ASP.NET Minimal API + EF Core. Обучение,
  прогресс, тесты, ачивки, поддержка, push. Лежит в репозитории: `aloria-api/src/Aloria.Api`.
- **Auth, `lk-api.alor.dev`** — SSO Алор.

### Целевое разделение

- **ИИ-режиссёр — отдельный сервис** (замена n8n). Единственный писатель. Пишет в два стока:
  (1) целевые цены — читает `terex.ordergenerator`; (2) контент-стор Aloria
  (новости/события/макро/календарь) — читает aloria-api. Приложению напрямую не отдаёт.
- **Клиентский read-API — расширяем aloria-api**, не новый сервис: чтение новостей
  (symbol + сектор + тип события), макро-лента (режим/ставка/календарь), материалы. Приложение
  переезжает с `api.alor.dev/news/graphql` на aloria-api.
- **Админка — пока тот же бэк** (admin-роутер уже есть). Отделим позже при необходимости.

```
  ИИ-РЕЖИССЁР ──пишет──►  целевые цены (стор движка)  ◄─читает─ terex.ordergenerator → стакан
   (симуляция,            новости/события/макро       ◄─читает─ aloria-api ──► Приложение
    RNG+LLM+формулы)             (стор Aloria)
        ▲
        └── АДМИНКА: ручной макроцикл, тюнинг распределений, журнал событий
```

Паттерн **read-model**: режиссёр — единственный писатель, остальные читают. Общая БД на этом
этапе — норма, не костыль.

## 10. Порядок работ

1. **Клиентский бэк + приложение (текущий этап).** Расширяем aloria-api доменом
   новости/события/макро + REST-эндпоинты; бэк **сидит случайные мок-данные** по тестовой
   вселенной; приложение красиво показывает новости/макро с нового API (репойнт `MarketNewsRepository`).
2. **ИИ-режиссёр.** Отдельный сервис заменяет мок-генерацию: RNG-сэмплер → LLM → формулы →
   целевые цены + новости.
